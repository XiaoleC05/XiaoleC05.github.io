## 1. 本项目的“三件东西”

| 概念 | 是什么 | 在哪 |
|------|--------|------|
| **源码** | Markdown、`_config.yml`、主题配置等 | 本机仓库、`main` 分支；你同步到 **Gitee** 的 `origin` |
| **生成结果** | 纯 HTML/CSS/JS，可部署的静态站 | 执行 `hexo generate` 后出现在 **`public/`**（勿手改，会被覆盖） |
| **线上站点** | 别人访问的网站 | **GitHub**：`XiaoleC05/XiaoleC05.github.io` 的 **`page`** 分支；访问 **https://xiaolec05.github.io/** |

记住：**改站 = 改源码 → 生成 → 部署**；`public/` 和远程的 `page` 分支由命令自动生成，一般不要直接编辑。

## 2. 目录结构说明

```
chenxiaole/                 ← 项目根（Hexo 根目录）
├── _config.yml             ← 全站配置（最重要）
├── package.json            ← Node 依赖与 npm 脚本
├── package-lock.json
├── scaffolds/              ← `hexo new` 时用的模板
├── source/                 ← 源内容（会参与生成）
│   ├── _posts/             ← 博客文章（Markdown）
│   └── ...                 ← 独立页面目录，如「关于」等
├── themes/                 ← 主题（可选本地主题；当前使用 npm 包 **Fluid**）
├── public/                 ← 生成输出（可删，hexo clean 会删）
├── .deploy_git/            ← 部署用临时目录（可忽略，勿提交）
└── docs/                   ← 本帮助文档
```

- **`source/_posts/`**：时间线文章。  
- **`source/` 下其它文件夹**：每个文件夹里可有 `index.md`，生成独立 URL（如「第一个页面」）。  
- **`themes/`**：主题代码；本仓库主题为 **`hexo-theme-fluid`**（配置在根目录 **`_config.fluid.yml`**）。

## 4. 最常用工作流程

### 4.1 只改配置或文章后发布

```powershell
hexo clean
hexo generate
hexo deploy
```

（PowerShell 7 下可写一行：`hexo clean && hexo generate && hexo deploy`。）

### 4.2 发布前本地看一眼

```powershell
hexo server
```

浏览器打开提示的地址（默认 `http://localhost:4000`）。按 `Ctrl+C` 停止。

### 4.3 用 npm 脚本（与 `package.json` 一致）

| 命令 | 作用 |
|------|------|
| `npm run clean` | 清理缓存与 `public/` |
| `npm run build` | 等同 `hexo generate` |
| `npm run server` | 本地预览 |
| `npm run deploy` | 部署 |

## 5. 写文章、页面与草稿

在**项目根目录**打开终端执行。

### 5.1 新文章（博客）

```powershell
hexo new post "文章标题"
```

- 会在 `source/_posts/` 下生成一个 `.md` 文件（本仓库 **`new_post_name: :title.md`**，文件名一般与标题相关，含中文时可能经 URL 编码，属正常现象）。  
- 打开该文件，在 **Front-matter**（文件最上面 `---` 之间）和正文里编辑。Front-matter 各字段含义见 **[§6 文章头部 Front-matter](#6-文章头部-front-matter)**。

#### 5.1.1 新文章完整流程：创建 → 本地预览 → 备份源码 → 上线

建议每次按下面顺序做，少漏步骤、方便回滚。

1. **进入项目根目录**  
   终端里 `cd` 到本仓库根（与 `_config.yml`、`package.json` 同级），再执行后续命令。

2. **创建文章骨架**  
   ```powershell
   hexo new post "你要显示的标题"
   ```  
   成功后终端会打印生成的 **`.md` 路径**，记下它；或在资源管理器里打开 **`source/_posts/`**，按修改时间排序找最新文件。

3. **编辑 Front-matter（文件顶部两排 `---` 之间）**  
   - **`title`**：页面标题，可与命令行里的标题一致或再润色。  
   - **`date`**：发布时间。若写成**晚于当前时刻**，且全站 **`future: true`**（本仓库为 `true`），则 **`hexo generate` / 线上首页可能暂时不显示该文**，直到日期到达；希望立刻出现在首页时，把 `date` 改为**当前或过去的日期时间**。  
   - **`tags` / `categories`**：按需填写；不写也可发，只是归档页分类较少。  
   - 其它字段（摘要、置顶等）见 **§6** 与 Fluid 主题文档。

4. **写正文（第二排 `---` 以下）**  
   使用 Markdown：`#` 标题、列表、代码块、链接等。 fenced 代码块建议写上语言（例如 **js**、**python**），便于主题高亮。

5. **配图（可选）**  
   本仓库 **`post_asset_folder: true`**：可为该文在同目录下建 **`与 .md 主文件名相同的文件夹`**，把图片放进去，正文按 [Hexo 资源文件夹](https://hexo.io/zh-cn/docs/asset-folders) 的写法引用。更多见 **[§7 Markdown 与图片资源](#7-markdown-与图片资源)**。

6. **本地预览**  
   ```powershell
   hexo server
   ```  
   浏览器打开 **`http://localhost:4000/`**，进首页或归档找到新文，检查排版、链接、图片。改完后保存 `.md`，刷新浏览器即可再看（一般无需重启 `hexo s`）。确认无误后终端 **`Ctrl+C`** 停止服务。

7. **（推荐）提交源码到 Git**  
   避免只部署、不备份：  
   ```powershell
   git status
   git add source/_posts/   # 若还有新图片目录，一并 add 对应路径
   git commit -m "posts: 添加 xxx"
   git push origin main
   ```  
   若你还配置了 GitHub 源码远程，按需 **`git push github main`**。详见 **[§12 Git 与双远程](#12-git-与双远程gitee--github)**。

8. **生成并部署静态站**  
   ```powershell
   hexo clean
   hexo generate
   hexo deploy
   ```  
   或使用 **`npm run clean`**、**`npm run build`**、**`npm run deploy`**。部署目标为本仓库 **`_config.yml`** 里 **`deploy`** 指向的 **`page` 分支**（详见 **[§11 部署到 GitHub Pages](#11-部署到-github-pages)**）。  
   推送成功后等待 **GitHub Pages 构建几分钟**，再访问 **https://xiaolec05.github.io/**；浏览器可 **强制刷新（Ctrl+F5）** 或无痕窗口排除缓存干扰。

**常见遗漏：**  
- 只执行了 `hexo g` 忘记 **`hexo d`** → 本地 `public/` 已新，线上仍旧。  
- **`date` 在未来** → 线上不显示；改日期后需重新 `generate` + `deploy`。  
- 大改主题或 `_config.yml` 后未 **`hexo clean`** → 偶发旧文件残留，可先 clean 再 `g`。

#### 5.1.2 编辑已有文章：定位 → 修改 → 预览 → 备份 → 上线

「编辑」包括改字、改图、改标签、改名、删文等。

1. **定位要改的源文件**  
   - 打开 **`source/_posts/`**，根据 **文件名** 或 **文件内 `title:`** 找到对应 **`.md`**。  
   - 若记得线上 URL（如 `/2026/04/12/某标题/`），可对照 **`permalink`** 规则（本仓库为 **`:year/:month/:day/:title/`**）反推目录与 slug；**`title` 在 front-matter 里改过**时，URL 中的「标题段」可能与磁盘文件名不完全一致，以 **Hexo 生成的实际链接** 为准（本地 `hexo s` 点进文章看地址栏）。

2. **在编辑器中修改**  
   - 只改正文：直接编辑 **`---` 以下** Markdown。  
   - 改元信息：编辑 **`---` 之间** 的 `title`、`date`、`tags` 等；改 **`date` / `updated`** 会影响排序与「未来文」是否展示（同 **§5.1.1** 中 `future` 说明）。  
   - 改配图：在 **与该文同名的资源文件夹**（若已创建）里替换图片，或改正文中的引用路径。无资源文件夹时，可把图放到 **`source/img/`** 等公共目录并在正文写绝对路径 **`/img/xxx.png`**（注意大小写与扩展名）。

3. **（可选）改文章文件名**  
   重命名 **`.md`** 后，若未自定义 **`permalink`**，URL 可能随新文件名变化，**旧链接会失效**；对外已分享过的文章，优先 **保留文件名** 或显式写 **`permalink`** 固定旧地址。

4. **本地预览**  
   同样 **`hexo server`**，打开该文逐段检查。

5. **备份与部署**  
   **`git add` / `commit` / `push`** 对应变更后，再 **`hexo clean && hexo generate && hexo deploy`**（或分步执行）。与新建文章相同：**部署推的是 `public/` 到 `page` 分支**，与 **`git push` 源码** 是两条线。

6. **删除一篇文章**  
   - 删除 **`source/_posts/` 下对应 `.md`**。  
   - 若存在 **同名资源文件夹**（`post_asset_folder`），**一并删除**该文件夹，避免孤儿文件。  
   - 执行 **`hexo clean`** 后再 **`hexo generate` + `hexo deploy`**，并 **`git commit`** 记录删除，避免别人或另一台电脑又把旧文加回来。

### 5.2 独立页面（如「关于」「友链」）

```powershell
hexo new page "关于"
```

- 一般在 `source/关于/index.md`（或类似路径）。  
- 是否在导航显示，取决于 **主题** 是否自动扫描或需在主题配置里添加链接。  
- **友链页**：访客可见的说明写在 **`source/links/index.md`**；**友链卡片数据**在 **`_config.fluid.yml` → `links` → `items`** 里增删（Fluid 主题的 `layout: links` 会读该配置）。  
- **项目页**：中文表格在 **`source/projects/index.md`**，英文在 **`source/en/projects/index.md`**；页面正文宜面向访客，不必写源码路径提示。

### 5.3 草稿（默认不公开生成）

```powershell
hexo new draft "草稿标题"
```

- 草稿通常在 `source/_drafts/`。  
- `_config.yml` 里 `render_drafts: false` 时，`hexo generate` **不会**把草稿发布到 `public/`。  
- 发布草稿：可用 `hexo publish`（将草稿移到 `_posts`），或手动移动文件并改日期。

## 6. 文章头部 Front-matter

每篇文章 **最上方** 用 YAML 写在两行 `---` 之间，例如：

```yaml
---
title: 文章标题
date: 2026-04-12 10:00:00
tags:
  - 标签一
  - 标签二
categories: 分类名
---
```

**注意（YAML 语法）：**

- `键: 值` 里 **冒号后必须有空格**，例如 `title: 我的标题`。  
- 值里若有特殊字符、中文逗号混用，用 **英文单引号** 包起来更稳妥，例如 `keywords: 'a, b, c'`。  
- 列表用 `-` 逐项写，或写成 `[a, b]`。

常用字段：

| 字段 | 含义 |
|------|------|
| `title` | 标题 |
| `date` | 发布日期时间 |
| `updated` | 更新时间（可选） |
| `tags` | 标签（列表） |
| `categories` | 分类（字符串或列表，视主题而定） |
| `permalink` | 自定义永久链接（可选） |
| `layout` | 布局，默认 `post` |

## 7. Markdown 与图片资源

本仓库 `_config.yml` 中 **`post_asset_folder: true`**：  
对某篇 `source/_posts/某文章.md`，Hexo 会允许同名文件夹 **`某文章/`** 放图片等资源，正文中可用相对路径或标签引用（具体语法以 [Hexo 资源文件夹文档](https://hexo.io/docs/asset-folders) 为准）。

**建议：**

- 图片文件名用英文、数字、短横线，避免空格。  
- 大图片可先压缩再上传，加快站点加载。

## 8. `_config.yml` 配置说明

修改后保存，再 `hexo generate` / `hexo server` 才能看到效果（部分项需 `hexo clean`）。

### 8.1 站点信息（Site）

| 配置项 | 作用 |
|--------|------|
| `title` | 站点标题 |
| `subtitle` | 副标题 |
| `description` | 描述（SEO、分享摘要） |
| `keywords` | 关键词，建议用引号包裹整串 |
| `author` | 作者名 |
| `language` | 语言，如 `zh-CN` |
| `timezone` | 时区，如 `Asia/Shanghai` |

### 8.2 网址（URL）—— 出错最多的一块

| 配置项 | 作用 |
|--------|------|
| `url` | **线上访问的完整站点根地址**，须与 GitHub Pages 实际地址一致（本仓库为 `https://xiaolec05.github.io`） |
| `root` | 若站点在子路径（如 `https://user.github.io/blog/`），`root` 应为 `/blog/`；用户页在根域名则 **`/`** |
| `permalink` | 单篇文章 URL 规则，当前为 `:year/:month/:day/:title/` |

若样式错乱、CSS 404，先检查 **`url` 与 `root`** 是否与浏览器地址栏完全一致（含 `https`）。

### 8.3 写作（Writing）

| 配置项 | 作用 |
|--------|------|
| `post_asset_folder` | 是否为每篇文章创建资源文件夹 |
| `render_drafts` | 是否渲染草稿 |
| `syntax_highlighter` | 代码高亮引擎 |

### 8.4 首页与分页

| 配置项 | 作用 |
|--------|------|
| `index_generator.per_page` | 首页每页文章数 |
| `per_page` | 全局分页每页条数 |

### 8.5 主题

```yaml
theme: fluid
```

更换主题后改这里，并确保 `themes/` 或 `node_modules` 里存在对应主题；阅读该主题的 README。

### 8.6 部署（Deploy）—— 与本仓库一致

```yaml
deploy:
  type: git
  repo: https://github.com/XiaoleC05/XiaoleC05.github.io.git
  branch: page
```

- **`repo`**：GitHub 仓库地址；若用 SSH 可改为 `git@github.com:XiaoleC05/XiaoleC05.github.io.git`。  
- **`branch`**：静态文件推送到的分支；**必须与** GitHub **Settings → Pages** 里选择的发布分支一致（当前为 **`page`**）。  
- 若改成 `main` 发布，则部署分支也要改成 `main`，并注意不要把 Hexo 源码覆盖掉（通常源码与站点分支分开更安全）。

## 9. Hexo 与 Git 命令速查

未全局安装 Hexo 时，可在项目根目录用 **`npx hexo …`**（与下表 `hexo …` 等价）。本仓库 **`package.json`** 还提供：`npm run build`（= `hexo generate`）、`npm run clean`、`npm run deploy`、`npm run server`。

### 9.1 Hexo

| 命令 | 说明 |
|------|------|
| `hexo init <文件夹>` | 新建空站点（本仓库已建好，一般不用） |
| `hexo new post "标题"` | 在 `source/_posts/` 下新建文章（默认布局 `post`） |
| `hexo new page "标题"` | 新建独立页面（如关于、友链；路径依主题/permalink） |
| `hexo new draft "标题"` | 新建草稿到 `source/_drafts/`（默认 `render_drafts: false` 不生成进 `public/`；预览用 `hexo s --draft`） |
| `hexo publish <草稿文件名>` | 将 `_drafts/` 中某篇移到 `_posts/` 并去掉 `published: false`（发正式文） |
| `hexo generate` / `hexo g` | 生成静态文件到 `public/` |
| `hexo clean` | 删除 `public/` 与数据库缓存；大改配置或主题后建议先 clean 再 `g` |
| `hexo server` / `hexo s` | 本地预览，默认 **http://localhost:4000/** |
| `hexo server -p 4001` | 指定端口（见下文第 10 节） |
| `hexo deploy` / `hexo d` | 按 `_config.yml` 的 `deploy` 把 `public/` 推到远程（如 GitHub `page` 分支） |
| `hexo list <type>` | 列出可用 `type`：`generator`、`renderer` 等，排查插件是否加载 |
| `hexo config key` | 打印合并后的某项配置（调试 `_config.yml` / `_config.fluid.yml`） |
| `hexo version` / `hexo v` | 查看 Hexo、Node、OS 及已加载插件版本 |

**常用组合**（发布前本地确认）：`hexo clean && hexo g && hexo s` 预览无误后，再 `hexo d` 或 `npm run deploy`。

### 9.2 Git（与第 12 节「双远程」配合）

| 命令 | 说明 |
|------|------|
| `git status` | 查看工作区与暂存区变更 |
| `git diff` | 查看未暂存修改；`git diff --staged` 查看已 `add` 的修改 |
| `git add <路径>` | 暂存指定文件；`git add -A` 暂存全部变更（含删除） |
| `git commit -m "说明"` | 提交暂存区；说明建议写清「改了什么」 |
| `git push origin main` | 推送到 **Gitee** 远程 `origin` 的 `main`（本仓库备份习惯） |
| `git push github main` | 推送到 **GitHub** 远程 `github` 的 `main`（若已按第 12 节配置） |
| `git pull origin main` | 从 Gitee 拉取并合并（协作前先 pull） |
| `git remote -v` | 查看所有远程名与 URL，确认 `origin` / `github` |
| `git branch` | 列出本地分支；当前分支前有 `*` |
| `git checkout -b <分支名>` | 基于当前提交新建并切换分支（实验性改动可用） |
| `git log --oneline -n 10` | 最近 10 条提交一行摘要 |

**注意**：**`hexo deploy`** 走的是 **deployer** 配置，与 **`git push`** 推送「整份源码仓库」是两条线；改文章/主题后既要 `git push` 备份源码，又要 `hexo d` 才会更新 GitHub Pages 上的静态站点。

## 10. 本地预览与端口占用

默认端口 **4000**。若提示端口被占用：

```powershell
hexo server -p 4001
```

或在 `_config.yml` 增加（若当前 Hexo 版本支持 `server` 段）：

```yaml
server:
  port: 4001
```

（以你本机 Hexo 版本文档为准。）

## 11. 部署到 GitHub Pages

1. 本地执行：`hexo clean && hexo generate && hexo deploy`。  
2. 使用 **`hexo-deployer-git`**，会向 **`repo`** 的 **`branch`**（`page`）推送 **`public/`** 内容。  
3. 在 GitHub 仓库 **Settings → Pages** 中：  
   - Source：**Deploy from a branch**  
   - Branch：**`page`**，目录 **`/ (root)`**  
4. 等待几分钟再访问 **https://xiaolec05.github.io/**。  
5. **HTTPS 推送**需要已登录 GitHub（凭据管理器或 Token）；失败时检查网络与权限。

**切勿**把部署分支与存放 Hexo 源码的 `main` 混用且随意改分支名，否则会出现「站点空白 / 404」。

## 12. Git 与双远程（Gitee + GitHub）

常见安排：

- **`origin`**：指向 **Gitee**，用于备份与协作 Hexo **源码**（`main`）。  
- **`github`**：指向 **GitHub** `XiaoleC05.github.io`，便于 `git push github main` 同步源码。  

**`hexo deploy`** 只负责把 **`public/`** 推到 `_config.yml` 里配置的 **`deploy.repo`** 的 **`page`** 分支，**不会**自动 `git push` 你工作区里的所有文件。

建议习惯：

- 改完文章或配置：`git add` → `git commit` → `git push origin main`（及按需 `git push github main`）。  
- 要更新线上：`hexo deploy`。

## 14. 插件说明

本仓库 `package.json` 中与生成相关的依赖包括：

- **`hexo-generator-*`**：首页、归档、分类、标签等页面生成。  
- **`hexo-renderer-*`**：渲染 Markdown、EJS、Stylus 等。  
- **`hexo-server`**：本地预览。  
- **`hexo-deployer-git`**：**必须**，否则 `deploy.type: git` 会报错。  
- **`hexo-generator-search`**：生成 **`local-search.xml`**，供 Fluid 站内搜索（**不扫正文**，范围含文章与独立页面标题，见 `_config.fluid.yml` 的 `search.field`）。  
- **`hexo-generator-feed`**：生成 **`atom.xml`**（RSS/Atom 订阅源）。

新增插件：`npm install hexo-某插件 --save`，再在 `_config.yml` 里按插件说明配置。

## 15. 常见问题排查

| 现象 | 可能原因 | 处理方向 |
|------|----------|----------|
| `YAMLException` / 配置报错 | `_config.yml` 冒号后无空格、中文标点混用 | 对照第 6 节与现有正确行格式修改 |
| `Deployer not found: git` | 未安装 `hexo-deployer-git` | `npm install hexo-deployer-git --save` |
| `Repository not found` | 仓库不存在或无权访问 | 确认 GitHub 仓库名；检查登录与 Token |
| 网站 404 / 无 Pages | Pages 未选分支或选错分支 | 选 **`page`** 且先成功执行 `hexo deploy` |
| 样式乱、资源 404 | `url` / `root` 与真实地址不一致 | 改成与浏览器访问根路径一致 |
| `src refspec main does not match any` | 未提交就 push | 先 `git commit` |
| 端口占用 | 4000 被占用 | `hexo s -p 4001` |
| PowerShell 里 `&&` 报错 | 使用 PowerShell 5 | 换 **PowerShell 7** 或用分号 `;` 分行执行 |

## 16. 升级与安全建议
